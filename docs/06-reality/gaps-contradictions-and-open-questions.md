# Gaps, Contradictions, and Open Questions

This is the current criticism backlog. Items remain open until evidence closes them; they are not hidden in optimistic release prose.

## Current user testing feedback

The [0.17.0 testing feedback](testing-feedback-0.17.0.md) records two open installer items: unreadable disabled-control text after clicking Install (`INSTALL-FB-001`) and automatic removal of previous installed versions in future releases (`INSTALL-FB-002`). The latter reinforces `UPG-001` and must preserve durable Coach data.

## Bristol pace-loss investigation acceptance

`GAP-023`: the app does not yet connect a selected race's pace change, tire/service history, comparable lap windows, corner traces and competing explanations into a reproducible investigation. The [September 22 Bristol case study](bristol-pace-investigation-2026-09-22.md) defines the measured example and required changes by app section. In that race the last eligible reference lap is 132 although the largest observed slowdown continues through 159; a generic "late" summary hides this distinction. The chart Clean filter is also weaker than coaching eligibility, and the first corner metric masks proximity exclusion as insufficient samples. The numeric pace-slope correction alone does not close this workflow gap. Closure requires completing the case in the native app with saved window identities, explicit exclusions, trace links and evidence for and against each explanation, without unsupported cause or damage claims.

## September 24 backend storage fixes

- `GAP-020` narrowed. With `LongPathsEnabled=0` (DESKTOP-SIM), raw archives made before the short `telemetry.ibt` name reach 258–275 characters under a longer Documents root. The copy was reported absent, copied again, and the rename failed with WinError 3, stopping the analysis. Raw-archive I/O now uses extended-length paths, so the existing copy is verified in place. Reproduced on DESKTOP-SIM with a real 81.7 MB Bristol race at a 269-character archive path: the previous backend failed in 0.2 s; the fixed backend analyzed it in 6.8 s without rewriting the copy. Following `TD-008`, a destination failure (disk full, access denied, locked or blocked path) no longer stops analysis: the analysis records that raw reanalysis is not yet durable, gives the cause, action and full archive path, and the next analysis retries. A changed source or digest mismatch still stops analysis. Long-path support covers the raw archive and the atomic write/copy primitives only; the history database, report listing and app readers still assume paths under 260 characters.
- `GAP-025` (new, partly closed): report copies. Reports were stored per `analyzed_at`, and the app re-analyzes a recording on every open, so each open added a full copy. The DESKTOP-SIM QA profile (a copy of the real data) holds 160 report directories (6.95 GB); 90 of them (5.35 GB) repeat an analysis already kept, including 19 extra copies of the 2026-09-21 Bristol race (0.80 GB). Reports are now keyed by `analysis_id` and replaced in place; three analyses of one real recording now leave one copy instead of three. Existing copies were not deleted. `coach_cli.py report-storage` (`ArchiveStore.report_storage_usage`) measures them read-only and protects copies named by the history index or a saved trial or tuning record. Closure needs a Settings action with an explicit user choice (`PORT-007`) that re-checks references and drops app caches naming a removed copy.

## Open product questions

1. What exact Windows versions, WebView2 versions, scaling factors, and minimum hardware define the support matrix?
2. External-service credentials are explicitly excluded from portable migration and require reconnection on the destination PC.
3. What source is authoritative for owned cars when iRacing does not expose ownership locally in a reliable supported form?
4. What threshold of real-session coverage is required for each telemetry-related release claim?
5. Starting Tune remains within Setups; Progressive Tuning remains event-linked follow-up unless user research justifies a navigation change.
6. Which optional AI behaviors, if any, are release requirements rather than roadmap ideas?
7. Raw finalized IBTs are retained until an explicit durable-data deletion action; retention periods for histories, logs, derived caches, and backups remain open.

## Resolution rule

Closing an item requires a specification update, implementation change when applicable, and evidence. A comment such as "works locally" or a screenshot without scenario provenance is insufficient.
