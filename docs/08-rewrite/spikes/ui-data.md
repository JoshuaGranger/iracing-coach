Scope: `companion-app/src` at `main` (8ce7170), read-only. Paths below are relative to `companion-app/src/` unless noted. Cites are `file:line`. Machine facts come from this PC (DESKTOP-JOSHUA), archive `C:\Users\joshu\Documents\iRacing Coach\data`, read with Git Bash and the Codex Python runtime. "inferred" = not directly observed. "UNKNOWN" = could not determine.

## 0. Findings that change the API design

1. **The UI never talks to the backend JSON directly.** Everything flows `McpBackendClient` -> `CompanionState.CallBackendAsync` (`iRacingCoach.Coordinator/CompanionState.cs:1043`) -> `RuntimeMapper`/`*Mapper` -> records in `iRacingCoach.Contracts`. The `analyze_iracing_race` envelope (`analysis_view`, schema "post-race-foundations-v23", `RuntimeMapper.cs:11`) is the only large payload; every other tool returns small JSON.
2. **Chart geometry is built inside Razor, not in a mapper.** The cursor config (`TelemetryWorkspace.razor:1632-1727`), SVG trace paths (`:2387-2411`), map projection and heat ribbons (`:1750-2240`) and all-lap aggregates (`:1699-1717`) are computed in the component from the full `AnalysisLapTrace[]`. The API must either ship the raw 160-bin traces and let TS redo this (about 1,100 lines of C# to port), or ship ready-made bounded series (see 4).
3. **`race-inspection.js` reads its data from DOM attributes** (`data-rows` JSON, `data-points` JSON), not from a function argument (`wwwroot/race-inspection.js:11-37`). It needs a thin TS wrapper that writes those attributes or a small refactor to accept objects. `analysis-telemetry-cursor.js` takes an object but needs Razor-rendered SVG with specific `data-*` hooks (3.2).
4. **No driver concept exists in the app today.** `driver_name` and `customer_id` are in each `analysis.json` `identity` block (observed: `{'customer_id': 1507810, 'driver_irating': 1636.0, 'driver_name': 'Joshua Granger'}` on the newest report; source `iracing-coach/skills/analyze-iracing-race/scripts/analysis_engine.py:1362-1364`). The Razor UI and `RecentRace` never read them. The driver landing is net-new; it needs a driver list keyed by `customer_id`.
5. **No persisted `race_investigation` exists on this PC.** `grep -rl race_investigation` over all 189 `reports/**/analysis.json` and all 29 `ui-analysis-cache/*.json` returned nothing, and the repo has no fixture with one. Investigation payload size is UNKNOWN (bounds in 1.2).
6. **`theme.generated.css` is not generated.** No script writes it; `ThemeParityTests.cs:13-52` only asserts that each token string in the hand-edited file equals `config/theme.dark.json`. Same for `iRacingCoach.App/Theme.Generated.xaml` (header comment claims generation, `:3`). See 3.
7. **Plan, saved Tests, Details, Replay and Ask are interleaved with v1 code**: the Sessions page renders a Tests panel (`SessionsPage.razor:15-58`), sessions show "Test saved/Can check a test" status (`:176-181`), and Race investigation Actions create trials (`CompanionState.Investigation.cs:110`). These are parked (D8). Cut lines are in 1.2.

## 6. Design rules that constrain layout (15 bullets)

Sources: `docs/01-product/companion-design-principles.md` (CDP), `docs/01-product/visual-companion-redesign-2026-09-22.md` (VCR), `docs/05-quality/ui-accessibility-and-performance.md` (UAP), `AGENTS.md`.

1. Every control, chart or screen must name the racing decision it improves, the action it enables and how a later recording shows the benefit; otherwise remove or consolidate (AGENTS.md, CDP lines 11-13).
2. Capability may grow; interface complexity may not (`UI-023`, UAP).
3. The investigation is one viewport-bound workspace: track map, comparison/run context and the six critical channels (speed, time gap, throttle, brake, steering, body slip) visible together at 1280x720; no page headline, instruction paragraphs, telemetry accordion or separate inspection slider (CDP:41-53, `UI-025`).
4. Driving inputs are never hidden in accordions; the familiar synchronized chart/map cursor stays (AGENTS.md, CDP:47).
5. Pointer motion and touch dragging inspect the charts directly with arrow/Home/End equivalents; map selection and inspection keep the same pair and area (CDP:47).
6. Show exact laps and exact run age (accumulated green exposure) beside each selected lap; run groups list their laps ("3 laps - 35, 36, 37"), never an ambiguous range (CDP:49, VCR "Comparison identity").
7. Observed trend and screened fit are distinct: the primary run line is a centered 5-observation median stopping at supported laps, breaking across gaps; no screened line extended into unsupported data, no shading or bands (VCR "Run trends", AGENTS.md).
8. Detected sections are neutral analysis labels, not official turn numbers; apply only confirmed merges and keep provenance (AGENTS.md, VCR "Track sections").
9. No target telemetry, directional groove labels, damage onset or repair-only time without backend evidence; "Not comparable"/"Not established" instead of unsupported Improved/Unchanged (AGENTS.md, VCR Gate 2).
10. Do not open the newest race unconditionally: restore a valid prior investigation or show the Sessions library; one visible session picker; new arrivals never silently replace the selection (VCR "Adversarial review").
11. Navigation is a thin labeled strip (Sessions, Setups, Live plus Settings) rather than a wide rail; compact 28 px command bar token; healthy-service chatter and success toasts are suppressed (VCR app-wide table, `UI-004`, `UI-014/018`; final format undecided per AGENTS.md).
12. Setups: changed and unknown values first, identical count with full values one step away; missing values never count as equal; comparison respects units and same-car compatibility (VCR app-wide table, `SetupPage.razor:96-108`).
13. Concise racing language: keep copy only if it states an observation, a material limitation, a decision or an action; limitations live in tooltips or one details control (`UI-011`, `UI-024`, CDP:33).
14. Color never carries meaning alone (labels, line style, geometry, size), semantic telemetry colors are not recolored by the accent, WCAG AA contrast, visible focus, reduced motion honored; structural motion uses the single 500 ms `--motion-structure`, cursor/hover/paint stay frame-local (`UI-009,015,017,020,022`, `ACC-001..006`).
15. Phone: 44 px selection targets and readable text over crammed fit, even if a modest scroll results (VCR "Desktop and mobile"); live tiles must tolerate 1-8 rows/columns (`LiveMonitorLayouts.cs:11-12`).

## 7. Unknowns and cautions for the API designer

- UNKNOWN: investigation payload size (no sample); measure after the first analysis with current profile v23 on the sim copy.
- UNKNOWN: whether the tailnet site will use HTTPS (affects clipboard and any service worker).
- Observed archive is old (newest report 2026-09-20, `analysis_profile_version` = `post-race-damage-repair-corner-phase-v8`, versus current `post-race-foundations-v23`): sizes above are pre-v23 and the files lack `race_investigation`, `track_geometry` and `race_replay` keys, which `RuntimeMapper.cs:526-531` reads. `driver_adjustments` is in the observed reports; the C# UI does not read it (grep: 0 hits).
- `analysis.json` per brief is 40-80 MB; the largest observed on this PC is 42.6 MB. The UI cache envelope drops some of it (13.2 MB for the largest entry), so the API payload for one investigation can be much smaller than the stored report.
- `ui-analysis-cache` is keyed by `sha256(phase|selector)` (`CompanionState.cs:4495`); a content hash key is needed once recordings arrive by NAS (selector depends on Windows paths).
- The setup library "newest 200" and "Race and test-day only auto-analyze" rules are in `LoadArchivedSetups` (`:4421`) and `QueueMissingHomeRaceAnalysis` (`:4103`), not in the backend; D9 needs the server to enumerate setups from recordings directly.
