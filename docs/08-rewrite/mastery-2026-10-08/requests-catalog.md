**What the August asks described, in his words.** A Windows "companion" over a deterministic local backend (Spec, 2026-08-05) with four product workflows: *Race planning* ("review fuel range, cautions, pit windows, prior performance, track knowledge, and coaching targets"), *Race analysis* ("show a concise Race Card first", the card being "Bottom line … Start … Long run … Strategy" plus a *Corner playbook* table by run phase and groove migration and three *Race triggers*), *Create a starting tune* ("review a race/Q starting package") and *Progressive tuning* ("Enter an entry/center/exit symptom after a run; receive one controlled change"). Around them: Live Telemetry tiles "like the old windows start menu tiles … drag-and-resizeable" (2026-08-05), a Live Monitor "movable, non-native-resizable, grid-based telemetry workspace" (2026-08-03), Technical data with "pit strategy, tire management, fuel management, racecraft & pace" and a Race replay (2026-08-07), Garage61 as a labelled beta, and "Race Coach AI" where "I want AI to be as useful as possible" (2026-08-15). The purpose: "to be my crew chief and engineering companion. To help me ascend to an elite racer. To understand how to be faster on the track, to understand how hard I'm being on the tires, to understand what pit strategy has the highest chance of victory" (2026-08-17); "a Windows application combining local iRacing telemetry with AI-powered driver coaching, race and pit-strategy analysis, tire-management insights, and setup development" (his email, 2026-08-18); planning that is "an engineer/crew chief/driver brief going into the race" and a "setup shop where we compare, analyze, and maybe even build setups" (2026-08-18); a tire model where "all these things combine to a predictable amount of tire wear … none of it is guesswork" (2026-08-15).

**What he judged by September.** "the hardest and most useful things remain frustratingly lacking" (2026-08-15); "race planning: essentially useless" (2026-08-18); "the microscopic gains we've made versus the effort that I put into describing it … got very old" (2026-09-20); "I need a companion. Not a fancy app that doesn't help." (2026-09-22). The north star followed: "5 features that win me more races" (2026-09-23).

**What exists today (OD D8, backlog, 2026-10-08).** A Rust collector on the sim, a Rust service with the Python worker on the mini PC, raw recordings on the NAS, a TypeScript web UI reachable over the tailnet. Shipped: the Sessions library (R/Q/P cards, filters), the race investigation (Race chart with position, runs, trends and context toggles; Runs; Sections with fastest/slowest clean laps, real racing lines and traces; Traces with the synchronized cursor), a Live page with the existing text cues and a direct layout editor, and the Setups library (self-filling, versions, compare, Tune this setup). Six fix rounds since 2026-10-04 addressed his visual and semantic complaints.

**What he asked for that is not in the app (open or parked).** The Race Card and Corner playbook as a product surface (Q64, Q73); Plan / the pre-race brief (Q72, Q78; BL #9); Technical-data Details with stop, tire and fuel cards and grades (Q4; BL #5); Qualifying review (BL #6); Replay (Q151; BL #8); Tests / driving trials (Q156; BL #10); Ask / Race Coach AI behind an API key (Q153, Q157; BL #11); the Crew Chief live mode with the whole field (Q94; BL #26) and the live racing line (BL #7); the Driver statistics page (Q62; BL #27); fuel-and-tire-over-run visuals in the "G61 direction" (Q14); applying a setup into iRacing or writing .sto (Q107-Q110, parking lot); setup version outcomes (pace, tire life) per version (Q119); a settled, predictive tire/physics model and baseline tuning from track geometry and physics (Q125, Q128-Q132); Garage61 reference laps inside the app (Q135-Q142, D10 only as a secret); penalties and repairs on pit markers (Q40); sections as iRacing sectors (Q59); the Kansas offline-session question (BL #32) and lab garage observations (BL #84).
