# Race Analysis

Race Analysis is the deepest workflow. It must let the user choose an event, open it directly, and inspect supported evidence without an extra chat or preview step.

## Race browser

| ID | Requirement |
| --- | --- |
| `RA-001` | The base page MUST list finalized Race events newest first. |
| `RA-002` | Reconnected/split recordings from one SubSessionID/session MUST group into one event. |
| `RA-003` | Qualifying and Race recordings from the same event MUST group under one event. |
| `RA-004` | The complete event row MUST perform one action: open that event's full analysis. |
| `RA-005` | The browser MUST NOT contain a permanent preview pane, detached Race Review, nested child-session buttons, or a second “open full analysis” step. |
| `RA-006` | Each row MUST use friendly available facts: local time, track/layout, car, series/scope, setup type, result, distance, and analysis state. When cached analysis supports them, the row MUST be at least as informative as Home by also showing green/caution laps, longest green run, run/stop count, pace trend/consistency, and measured tire or supported control-load context. |
| `RA-007` | Search and filters MUST operate only on recorded/indexed fields and MUST adapt when a category is absent. |
| `RA-008` | Cached analysis SHOULD open effectively immediately; reanalysis MUST be explicit. |
| `RA-009` | Active, changing, zero-record, truncated, or trailing-partial IBTs MUST be deferred without advertising an artifact. |
| `RA-010` | Selecting an event MUST immediately open its Race telemetry when present. Slower reads MUST show a quiet loading state inside the telemetry panel; the user must not toggle another session to trigger loading. |

## Integrated insight contracts

### Technical data

- `RA-060`: The Race workspace MUST label its study/results section `Technical data`; `Race review` is superseded. Its default state MUST summarize result, totals, grades, and at most the changing useful priorities without repeating a detached Race Card or static methodology prose.
- `RA-060A`: The default Technical data surface MUST be a fixed-screen two-by-two overview with exactly four purposeful categories: `Pit strategy`, `Tire management`, `Fuel management`, and `Racecraft & pace`. Each quadrant MUST show compact race-specific results, charts, or comparisons rather than invariant help text. At 1280x720 it MUST fit beneath the compact event bar without page-level scrolling, clipped controls, or inaccessible content.
- `RA-060B`: Activating any overview quadrant MUST replace the overview with one full-area interactive investigation for that category. A visible, keyboard-operable Back control MUST restore the same overview without changing event, phase, lap selection, or the other category state. The investigation MAY scroll internally only when its evidence cannot be made legible within the fixed area.
- `RA-060C`: Each category and investigation MUST follow `RA-045A`: supported facts remain visible, unsupported submetrics identify the actual missing prerequisite and useful recovery action, and the absence of one metric MUST NOT erase unrelated evidence. No category may manufacture completeness to preserve the two-by-two visual balance.
- `RA-060D`: The overview and its drill-ins MUST expose the same complete set of supported material findings. The overview MAY compress wording and the drill-in MAY add graphical context and explanation, but an arbitrary item cap MUST NOT hide a finding that exists only after opening a category. Internal evidence/provenance remains inspectable in the analysis contract; primary UI copy MUST speak in driver terms rather than implementation-source language.

### Corner comparison

- `RA-070`: MUST include every supported material recorded track area. Internal segmentation terms such as `load zone` MUST NOT be exposed as the primary user label.
- `RA-071`: SHOULD separate early/middle/late phase and entry/center/exit where evidence supports it.
- `RA-072`: SHOULD show entry speed, brake onset/peak/release, minimum speed, steering work, throttle pickup, exit speed, and tire-management instruction when supported.
- `RA-073`: Exact targets and groove direction MUST obey comparison and geometry gates; relative coaching remains acceptable when exact targets are unavailable.
- `RA-074`: Corner zones MUST come from recorded/derived session segmentation. The UI MUST NOT manufacture generic corner names when segmentation is absent.

### Runs and tires

- `RA-080`: MUST define runs from confirmed service boundaries, not file boundaries or pit-road crossing alone.
- `RA-081`: MUST show available lap bounds, flag mix, pace/falloff, fuel, tire endpoint, service, and clean/confounded status.
- `RA-082`: Measured tire remaining at a confirmed service belongs to the preceding run.
- `RA-083`: Final-run wear MUST remain unmeasured when no service observation exists.
- `RA-084`: Blank headings/columns are forbidden; omit unsupported fields.
- `RA-085`: Tire management MUST distinguish measured service snapshots, the existing within-session calculated tire-wear proxy, and learned predictions. A measured endpoint MUST never be replaced or relabeled by a prediction, and the proxy MUST remain a proxy-calibrated session visualization rather than learned O/M/I wear.
- `RA-086`: When a compatible local tire model has sufficient evidence, Technical data MAY show predicted remaining O/M/I wear, laps remaining, pace cost, and sustainable capability pace with confidence and low/high bounds. Every prediction MUST identify the matched context and sample support; below the minimum evidence threshold it MUST be unavailable rather than extrapolated.
- `RA-087`: Initial learned tire coverage MUST be explicitly NASCAR-first. Unsupported car families, compounds, setup scopes, or conditions MUST not receive a NASCAR-derived value merely because the UI has room for one.
- `RA-088`: Garage61 representative laps are an eventual required comparison source for the mature tire/capability model, but local recorded history MUST remain useful offline. An external reference MUST remain visually and mathematically distinct from the user's measurements and local predictions and MUST obey the scope/provenance gates in `G61-004` through `G61-009`.

### Fuel & Strategy

- `RA-090`: MUST show supported green/caution burn, observed consumption, range, reserve, required stops, pit targets, and recorded stop context.
- `RA-091`: MUST call deterministic output fuel feasibility unless position, pit-loss, rules, cautions, overtime, and history justify stronger optimization language.
- `RA-092`: A page MUST NOT present contradictory range availability and exact range claims without a traceable distinction.
- `RA-093`: A two-tire versus four-tire retrospective MUST appear only when both calls are confirmed. It SHOULD compare available per-corner O/M/I wear, service duration, following-run clean pace, green-lap sample, caution state, fuel context, and pit-cycle position. Missing dimensions MUST be withheld, not zero-filled. Without race rules or comparable historical strategy outcomes, the app MUST NOT claim legality, a mandatory call, causation, or an optimal recommendation.

### Pit and repairs

- `RA-100`: MUST separate incident points, pit road, stall, service, tow, mandatory repair, optional repair, and fast-repair confirmation.
- `RA-101`: Overlapping clocks MUST be parallel and MUST NOT be added into repair-exclusive loss.
- `RA-102`: Zero recorded repair/tow channels may support “No recorded tow/repair workload”; absent channels may not.
- `RA-103`: Repair/tow/candidate laps MUST be excluded from ordinary clean trends, targets, setup comparisons, and pit-loss learning by default.

### Setup and evidence

- `RA-110`: Race Analysis MUST NOT show a setup panel unless the selected recording contains useful, readable setup values that materially change the analysis.
- `RA-111`: Evidence coverage, exclusions, provenance, and technical identifiers belong in diagnostics or a subordinate disclosure, not the primary workspace.
- `RA-112`: Repeated limitations that are invariant across races belong in a tooltip or documentation, not a primary card.

## Grading

Grades use `A+` through `F` and the versioned `race-execution-v2` rubric: Pace 30%, Consistency 20%, Tire Management 20%, Strategy 15%, and Racecraft 15%. Only categories with supported, driver-attributable evidence contribute; their configured weights are normalized across the available set. Damage-, repair-, pit-, caution-, traffic-, and reason-code-confounded evidence is excluded where recorded. Pit/tow counts do not become a Strategy score, and raw position change does not become a Racecraft score. A+ is gated until an external, condition- and setup-comparable field-strength cohort exists.

The UI grade audit exposes rubric version, configured weight, effective available-evidence weight, evidence kind, inputs, limitations, and deterministic provenance. Real-field calibration remains a product/test gap; a versioned formula and passing tests are not external validation.

## Current implementation evidence

The binding major-round target supersedes `Race review` with Technical data, adds Race replay, replaces recorded-path-only map presentation with exact-configuration layered vector geometry and the `Type` semantics in `RA-050B`, makes named Analysis layouts global and portable, permanently retains finalized raw IBTs, and adds the guarded NASCAR-first tire/capability learning contract. Development source and focused implementation-specific tests now cover these contracts, but they remain acceptance scope until the exhaustive changed-surface matrix, representative recordings, performance checks, and applicable lifecycle/model evidence pass. Specification or source presence alone is not product acceptance.

The deterministic engine now derives signed vehicle sideslip in degrees as `atan2(VelocityY, VelocityX)` only from paired finite velocity samples with positive/usable forward velocity and at least 5 m/s planar speed; invalid samples remain gaps, and Yaw Rate is untouched. Python tests passed 19/19, the coordinator mapper check passed 1/1, and one recorded Iowa IBT yielded 542 valid values plus 9 guarded gaps across four laps. This is scoped evidence for the derivation and mapping, not a native `SlipAngle` channel, tire-slip measurement, or broad cross-car correctness claim.
