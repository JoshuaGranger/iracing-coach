# Sessions library (`web/src/sessions/`)

Page: `pages/sessions.tsx`. Specification: `docs/08-rewrite/web-round-2-plan.md`, "Sessions" (backlog #17, #19, #18), "Round 3" (#33) and "Round 4" (#50-#57). Round 1's session tiles are gone; the list is one compact card per event, a 0.75 rem gap between cards (#50).

| File | Holds |
|---|---|
| `model.ts` | Events and phases (running order P, Q, R), filters (`Selection`, `filterSessions`, `facetOptions`), the cell rules (`phaseSlots`, `colouredFigures`, `phaseLayout`, `phaseColumns`), analysis exceptions, `eventPhaseOptions`. Pure; unit-tested. |
| `dates.ts` | Local date and time (audit S1). |
| `library.ts` | `useLibrary(customerId, library)`: the whole library in 200-row pages under one cache key per library (`main` keeps the plain URL); the filters work on it here. |
| `event-row.tsx` | `EventRow` (identity and phase cells) and `PhaseCell`; `SetupLock` and `LockIcon`, the Fixed/Open lock glyph (#51). |
| `phase-hues.test.ts` | The three phase hue tokens, shared with the investigation's P · Q · R selector (#52). |
| `silhouette.ts`, `track-silhouette.tsx` | Track silhouette from the analysis geometry, about 1.5 rem tall, fetched once per track layout when its row is on screen, kept in memory and in the device's storage. |
| `tab-memory.ts` | The last tab per session, remembered silently from the hash; the cell opens there. |
| `sessions.css` | All styling. Race data colours come from `--race-*`, phase hues from `--phase-practice-hue`, `--phase-qualify-hue`, `--phase-race-hue`, the car stripe from `--car-*`. |

## The card

- **One card per event** (#50): its own border and radius, a 0.75 rem gap to the next, no shared borders. The setup lock sits in its top-right corner (#51): closed for a fixed setup, open for an open one, the meaning on hover (`title`) and as the accessible name (`role="img"`, `aria-label`). A phase whose setup differs from its event carries its own lock beside its name.
- **Three blocks** (#33): the race is the card's subject, practice and qualifying its preamble. The identity ends at a divider; each phase is its own panel (border, radius, `--color-surface2`) across a gutter, with a `P`, `Q` or `R` badge at its top-left and its phase hue as a left edge and a faint header tint (#52; the race the strongest).
- **Identity** (left, 14 to 17 rem): silhouette (1.5 rem) and track, `config · date`, car stripe and car name (the series is in its tooltip, not drawn).
- **Phases**: one panel per phase, in running order, sized by `gridTemplate` (fractions: race 1.9, practice 1, qualifying 0.7, so a phase keeps its edge in every row). `phaseLayout` takes the phases present in what is shown, so a phase keeps its column in every row (two events line up to compare) and a filter that leaves only races leaves one column. A repeated phase (two practices) follows running order.
- **Layout by the row's own width** (container queries, not a device test): at 62 rem and wider the identity is at the left of the cells; below that it is a line above them; below 40 rem (a phone) the phases stack as rows. Nothing sits behind a disclosure.
- **Cell** (`cellSlots` by `cellKind`): practice shows Pos, Best, Long run (`longest_run_laps`, laps without a reset to the pits or garage) and Fall-off (`longest_run_pace_loss_s`, the backend run's last minus first clean lap, `+0.21 s`); qualifying shows Pos, Lap 1, Lap 2 (`timed_lap_1_s`, `timed_lap_2_s`); both in the quiet classes `.sx-qv`/`.sx-qp` (14 px, secondary colour; the type audit counts them as secondary). Pos is `P3 / 24` (#55, `classification`): the official place over the field size (`results_position`, `field_size`, sent together from a later recording of the event), else the last recorded position alone, never a recorded place over an official field. The race: a 4 x 2 grid, columns as wide as their figures. The header slot (the badge and phase name over the time) and the seven labelled slots: finish (`P4 ▲8 from P12`: the change against `start_position`, the official grid, and its reference named, #56), Grn · Cau, best, pace, stops, Burn (`fuel_per_lap_gal`, the backend's green burn per lap, `0.47 gal/lap`, #57), Long run (#54). A missing value is `—`. A phase with no figures shows its lap count and the one exception chip that explains it. The whole cell is the link when the phase can open. A race cell narrower than 26 rem (a phone) puts its header on its own line over three columns of figures, so no figure is cut.
- **Type**: the owner's minimums (2026-10-03) beat the plan's 0.75 rem: names 16 px (`--text-body`), figures 15 px (`--text-data`), labels and secondary lines 14 px (`--text-compact`). The row grows to fit; `perf/type-scale.mjs` selects `.sx-id h2`, `.sx-meta`, `.sx-car`, `.sx-l`, `.sx-v` and `.sx-p`, so the audit measures them. No local `--sx-*` tokens: the stylesheet reads the theme's tokens.

## Rules that are easy to get wrong

- **Colour budget.** Gain or loss on the position change (race only), the green-flag colour on a green-lap count above zero (#53), amber on a caution count above zero, the phase hue on the edge and badge, the car stripe. Nothing else: the finish is a plain number (no win flag), its `from P12` reference is muted, best, pace, stops, burn and long run carry no colour, there is no panel fill and no glow. The event's fastest lap is marked by weight (`data-event-best`), never by colour, and never across phases. `colouredFigures` is the tested budget: at most three per cell.
- **The finish change** is measured against `start_position` (the grid from the session results, else the backend's position at the green flag), never `starting_position` (the first recorded position). Without `start_position` there is no arrow and no reference.
- **Pace slot.** The server's `green_pace_median_s` then the backend trend (`pace_slope_s_per_lap`) with its sign.
- **Chips.** Fixed/Open is a lock glyph, not a chip. Exception chips (`Not analyzed`, `Failed · reason`, `Deferred · reason`, `Queued`, `Analyzing`) appear only on a phase that is not ready; `Analyze` and `Retry` are the chip's own action. A ready phase shows nothing.
- **Filters** sit in the page heading by the shared width rule (`ui/filter-bar.tsx`): inline at the right when they fit, else `Filters · N` (popover on a pointer, sheet on touch). No library control: `lab` only by `?library=lab` in the URL (#34). Any chosen value within one filter, all filters together. The selection is saved as `session_filters` in the driver's prefs (the query values of `GET /sessions`: car_path, track name, series name, `race`/`qualify`/`practice`, `fixed`/`open`) and mirrored on the device only for the first paint. The Setup filter appears once a session states its setup type. Each dropdown button carries its own choice and clears from inside its list; no chips, no Clear in the heading (#35, #36).
- Fixed or Open comes from `is_fixed_setup` (true fixed, false open); null means the recording does not say: no lock, never read as open.
- The investigation header's P . Q . R selector takes the event's phases and their analysis state from the session detail (`event_sessions`), in the shell (`ui/investigation-slot.tsx`); its segments use the same phase hues (`PHASE_HUE` in `investigation/ui/PhaseSelector.tsx`).
- Round 1 figures kept: event best over the whole event whatever the filter shows (`groupEvents`), longest run and pace on every cell, the saved filter selections.
